# Three-Month Project Roadmap

Use this as a plan for the next three months. Mark a task complete only after doing it and save evidence (test results, screenshots, commits, or notes).

## Month 1 — QA foundations and documentation
### Week 1: Repository setup
- [ ] Create the GitHub repository and add this starter project.
- [ ] Learn `git status`, `git add`, `git commit`, `git log`, and `git diff`.
- [ ] Add your actual environment details to the test plan.
- Evidence: first commit and repository README.

### Week 2: Test design
- [ ] Expand the test case sheet to at least 20 useful cases.
- [ ] Include positive, negative, boundary, usability, and compatibility cases.
- [ ] Review test cases for clear expected results.
- Evidence: updated CSV and commit.

### Week 3: Test execution
- [ ] Execute the cases against the chosen practice website/app.
- [ ] Record actual result, status, date, and evidence.
- [ ] Report only issues you can reproduce.
- Evidence: completed execution rows and genuine bug reports.

### Week 4: Defect lifecycle
- [ ] Create GitHub issues for project tasks or observed defects.
- [ ] Practice labels, assignees, milestones, and issue discussions.
- [ ] Write a short weekly test summary.
- Evidence: issues and weekly summary.

## Month 2 — Git workflow and automation
### Week 5: Branching
- [ ] Create a feature branch.
- [ ] Make a documentation improvement.
- [ ] Open a pull request and merge it after review.
- Evidence: branch and pull request history.

### Week 6: Playwright basics
- [ ] Run the starter tests.
- [ ] Learn `page.goto`, `page.title`, locators, and assertions.
- [ ] Add two stable checks.
- Evidence: passing test run and commit.

### Week 7: Test organization
- [ ] Group tests by feature.
- [ ] Add meaningful test names.
- [ ] Use reliable role/text locators where appropriate.
- Evidence: organized test files.

### Week 8: Debugging and reporting
- [ ] Practice headed mode and traces/screenshots on failure.
- [ ] Investigate any real failing tests.
- [ ] Document known limitations.
- Evidence: test report and notes.

## Month 3 — Regression, polish, and interview readiness
### Week 9: Regression suite
- [ ] Select critical flows for a small smoke/regression suite.
- [ ] Rerun tests after each change.
- [ ] Record pass/fail counts truthfully.
- Evidence: regression execution summary.

### Week 10: Cross-browser checks
- [ ] Configure a second browser if your computer supports it.
- [ ] Run the same smoke checks.
- [ ] Record any observed differences.
- Evidence: browser matrix.

### Week 11: Portfolio review
- [ ] Improve README setup instructions.
- [ ] Add screenshots or report artifacts that contain no personal data.
- [ ] Remove unfinished claims and explain known limitations.
- Evidence: clean repository and documentation.

### Week 12: Final report
- [ ] Summarize test scope, number of cases executed, actual outcomes, and known issues.
- [ ] Explain one bug report and one automated test in your own words.
- [ ] Prepare a 2-minute project walkthrough for interviews.
- Evidence: final report and complete GitHub history.
